# LecOrg 官网完善设计

## 目标

将当前的实验室单页官网完善为一套可展示团队文化、在读成员、往届优秀成员与发展历史的页面。首轮使用明确标注为 Mock 的成员与去向数据；后续收到 Excel 表格后，仅替换数据层即可呈现正式内容。

## 范围

- 保留首页、宗旨、成员和团队历史四个现有主题区块。
- 新增“往届优秀成员”区块，作为普通成员区块之后的独立全屏内容。
- 改用顶部固定横向导航，提供首页、宗旨、成员、优秀成员、历史五个锚点入口。
- 在桌面端使用整屏分段滚动；一次滚轮或键盘翻页只进入相邻的完整主区块，不停留在两个区块中间。
- 在小屏设备保留自然纵向阅读，防止内容超出一屏时被裁切或无法阅读。
- 以 2010 年 6 月成立、约 30 人、每周 28 小时考勤、例会/学习交流、竞赛与项目实践，以及“学以致用，服务学校，走向社会”为临时团队介绍依据。

## 不在本轮范围内

- Excel 上传、在线编辑、持久化存储或后台管理。
- 登录、注册和 PDF 参考图中的外部站点功能。
- 将当前成员的占位头像替换为真实照片。

## 页面与交互

### 顶部导航

导航固定在页面顶部，以横向文字链接展示五个区块。当前所在区块有清晰的视觉状态；点击导航平滑切换至目标区块。移动端允许横向滑动导航项，不压缩或隐藏必要入口。

### 分段滚动

主内容由五个语义化 section 构成。桌面端以一个视口高度为主单位，使用滚动捕捉与滚轮节流控制相邻区块切换；在动效期间忽略连续滚轮输入，避免越过区块。键盘的 PageUp、PageDown、Home、End 也遵循同一套切换逻辑。用户启用“减少动态效果”时，保持可访问的正常滚动和锚点导航。

### 成员

保留“成员”区块及按届筛选；本轮继续使用 Mock 的在读成员数据。该区块只承载在读成员，不混入毕业去向信息。

### 往届优秀成员

新增独立区块，按届从新到旧分组。每张横向信息卡包括：姓名、首字头像、去向标签（保研、考研或就业）、目标学校/公司以及可选的学历或补充信息。颜色仅辅助区分去向，文字也明确表达类型。首轮展示 2025 至 2021 届的 Mock 数据，所有数据集中于独立文件并在页面注明“Mock 展示”。

### 团队历史

保留时间轴视觉形态，使用与 PDF 团队介绍一致的临时历史节点，替换当前不具事实依据的 2014—2026 示例故事。收到正式资料后统一从数据文件更新。

## 架构与数据流

组件只负责展示与交互；团队简介、成员、优秀成员、里程碑和导航项分别由 `src/data` 或 `src/config` 下的结构化 TypeScript 模块提供。优秀成员定义为独立类型，字段包括 `id`、`name`、`cohort`、`outcome`、`organization` 与可选 `detail`。页面由入口组件按顺序组合各 section；导航和整屏滚动控制只依赖 section id，不依赖具体文案或数据。

## 错误处理与可访问性

- Mock 数据为空时，优秀成员区块显示明确的空状态，不渲染空白栅格。
- 所有交互元素使用原生按钮或链接，提供可读名称与键盘焦点样式。
- 头像使用成员姓名作为替代文本；纯装饰元素对辅助技术隐藏。
- 非触控滚动控制不会阻止链接、按钮、表单控件或可滚动卡片内部的默认行为。

## 验收标准

1. 桌面端从任一主区块滚动一次后停在相邻完整区块，而非两个区块之间。
2. 顶部导航可定位全部五个区块，并正确反映当前区块。
3. 当前成员筛选仍可用；优秀成员独立按届展示并显示三种 Mock 去向样式。
4. 团队历史仍可浏览，内容不再沿用原有虚构的 2014 年创立叙述。
5. 页面在窄屏下可完整阅读，导航与成员信息可操作。
6. 项目 lint 与 production build 均通过。
